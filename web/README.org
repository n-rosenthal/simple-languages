#+title: TAPL playground (WebAssembly)

Um REPL no navegador para as linguagens do TAPL. Todo o interpretador
(scanner, lexer, parser, tipos, semântica estrutural e natural, máquina
virtual, definições) é o mesmo código Rust do crate principal, compilado para
WebAssembly. Este diretório contém só a cola e a página.

* Compilar e rodar

Requisitos: Rust (com o alvo =wasm32-unknown-unknown=) e =wasm-pack=.

#+begin_src sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack

./web/build.sh serve        # compila e abre http://localhost:8080
#+end_src

Sem o script:

#+begin_src sh
wasm-pack build web --target web --out-dir www/pkg --release
python3 -m http.server 8080 -d web/www
#+end_src

A página precisa ser servida por HTTP: o navegador não carrega módulos ES nem
=.wasm= de =file://=.

* Renderização em LaTeX

Cada resposta do interpretador é uma lista de blocos (=Block= em
=src/common/document.rs=): títulos, texto, erros e fórmulas. Uma fórmula tem
três visões:

| visão   | para quê                                                  |
|---------+-----------------------------------------------------------|
| =web=   | LaTeX para o KaTeX (renderizado na página)                |
| =tex=   | LaTeX para =pdflatex= (=mathpartir=), botão "copiar LaTeX" |
| =text=  | o texto do terminal (botão "texto")                       |

O KaTeX não tem =\inferrule*= nem =\textsc=, então a versão =web= desenha cada
regra como =\dfrac= (as árvores de derivação aninham por recursão) e o nome da
regra vai à direita da barra, em =\text=. O que é renderizado:

- *termos e tipos*: o =ToLatex= de cada linguagem;
- *derivações* (tipagem e big-step): árvores de prova;
- *traces* da semântica estrutural: cadeias =t → t'= com a regra sobre a seta;
- *sintaxe* e *regras de inferência* de cada linguagem, no painel "Referência"
  (premissas e conclusão de cada regra vêm de =rules!=, em =Schema=).

O KaTeX está em =www/vendor/katex= (MIT, só fontes =woff2=), então a página
funciona sem CDN.

** Conferir o LaTeX

Despeja todo o LaTeX web de todos os exemplos, modos, sintaxes e regras e passa
tudo pelo KaTeX em modo estrito:

#+begin_src sh
cargo run -q --example dump_latex | node web/tools/check-latex.mjs
#+end_src

* Programas, erros com posição e capacidades

*Programas.* A caixa de entrada aceita várias linhas e várias instruções. As
instruções se separam por =;;= (que, ao contrário de =;=, não faz parte da
sintaxe de nenhuma linguagem do TAPL) e podem ocupar várias linhas:

#+begin_example
not = λb:Bool. if b then false else true ;;
twice = λf:Bool->Bool.
          λb:Bool. f (f b) ;;
twice not true
#+end_example

Um programa para na primeira instrução que falha. /Enter/ executa; se o texto
acabou cedo demais (um parêntese aberto, um =λx:A.= sem corpo), /Enter/ insere
uma quebra de linha. /Shift+Enter/ sempre quebra a linha e /Ctrl+Enter/ sempre
executa. No terminal, uma linha incompleta pede continuação com =...=, e uma
linha em branco executa.

*Erros com posição.* Um erro de sintaxe mostra o trecho do fonte com um =^=, com
a linha e a coluna contadas no programa inteiro:

#+begin_example
syntax error: unexpected character `#`
 --> 3:5
  |
3 |   y #
  |     ^
#+end_example

As posições são offsets em =char=s no texto todo (=Span= em
=src/common/source.rs=); o trait =Diagnostic= (=src/common/diagnostic.rs=) dá a
mensagem, a posição e se a entrada está incompleta. Erros de tipo e de
avaliação ainda não têm posição, porque os termos não guardam de onde vieram.

*Capacidades.* Uma linguagem que não define uma semântica usa um marcador:
=NoTyping=, =NoSmallStep=, =NoBigStep= ou =NoCompile=. O seletor de modo omite
o que não existe, o modo =full= mostra "not defined" no estágio, as leis que
dependem do que falta são puladas e a referência não lista as regras ausentes.

#+begin_src rust
type Typing   = NoTyping<Term>;                // sem sistema de tipos
type Small    = NoSmallStep<Term>;             // sem semântica estrutural
type Big      = NoBigStep<Term, Value>;        // sem semântica natural
type Compiler = NoCompile<Term, Value>;        // não compila para a máquina
#+end_src

* Testes

#+begin_src sh
cargo test --manifest-path web/Cargo.toml    # a cola, no alvo nativo
#+end_src

A lógica do interpretador é testada no crate principal (=cargo test=).

* Publicar

Copie =web/www/= (com =pkg/=) para qualquer hospedagem estática, por exemplo
GitHub Pages. Não há servidor: a execução é toda local.

* Limites

O interpretador roda no navegador, então há limites (em
=simple_languages::common::interpreter=): linha de até 2 000 caracteres, 100
níveis de parênteses e no máximo 20 000 passos (=:fuel=). Termos divergentes
(como \omega) terminam por falta de passos, e a profundidade de big-step de
=stlc= é limitada a 200.

* Acrescentar uma linguagem

Implemente =Language= no crate principal e registre em =src/registry.rs=
(=RUNNERS= e =SESSIONS=). A página a lista sozinha: seletor de linguagem,
exemplos e definições vêm de =Language::examples= e =SUPPORTS_DEFINITIONS=; a
sintaxe vem de =Language::syntax= e as regras, do esquema declarado em =rules!=:

#+begin_src rust
rules! {
    pub enum TypingRule {
        Var => "T-Var" { [r"x{:}T \in \Gamma"] => r"\Gamma \vdash x : T" },
    }
}
#+end_src
